# 景区图片与数据来源策略

景区图片的目标是兼顾实体准确性、清晰度和观赏性。任何来源都不能保证所有景区都有足够高质量素材。

## 主图来源

主图是用户进入景区页后最先看到的大图，因此优先保证“这张图确实属于当前景区”和“能代表景区”，而不是单纯追求数量或分辨率。

通常优先使用 Wikimedia 等高可信公共图片、官方页面、高德 POI 和已缓存候选，并通过名称、城市和视觉内容校验实体匹配。主图与画廊取舍不同：主图更重视准确性和代表性；画廊更重视官方来源、清晰度和多样性。高分辨率图片如果明显不是当前景区，不应因为清晰而成为主图。

## 画廊来源

画廊优先使用官方文旅局、景区官网和地方政府公开页面提取的图片。官方来源优先级高，主要因为它们与景区管理或宣传主体更接近，图片来源和所属实体通常更容易追溯，也更可能代表景区正式开放的景点。

官方来源仍可能分辨率低、构图单一、包含海报文字或长期未更新，因此“官方”不等于画质最好，也不等于每张都能直接使用。官方素材不足时，再使用高德主 POI、相关附近 POI 和 Wikimedia Commons 等候选，并继续做尺寸、重复和语义匹配。

Wikimedia Commons 等社区图片覆盖面广，但可能重复、构图相似、元数据错误或与景区关系较弱，因此不应默认占满画廊。官方来源、实体相关性和素材质量需要共同判断。

## 图片分辨率

原图分辨率是清晰度的上限。若原图本身很小，页面放大到主图或手机 Retina 屏幕尺寸时，浏览器只能插值放大，边缘和细节会显得发糊。服务端为节省带宽进行有损压缩，也会丢失细节；压缩率过高时，即使原图尺寸足够，文字、树叶和建筑边缘仍可能出现块状或涂抹感。

系统优先选择高分辨率原图，并限制异常小图和超大文件。素材不足时会适度降低分辨率门槛，以补足约 6 张画廊图片。降低门槛只影响候选数量，不表示低分辨率图片更准确；页面用大尺寸展示时仍可能模糊。

## 图片压缩与缓存

远程图片会下载到本地媒体目录，再通过后端地址提供给页面。缓存的主要作用是减少重复下载、降低第三方站点限流或失效的影响、避免浏览器跨域问题，并让同一图片在后续访问中更快加载。

缓存命中不代表图片一定最新或清晰；如果缓存的是低分辨率原图，后续展示仍会模糊。缓存文件也不应改变图片内容含义。服务端若进行压缩、缩放或裁剪，应保留主要主体和合理比例，并把处理后的质量责任与原始来源区分开。

## 图片去重

系统使用图片哈希或感知哈希识别完全重复和近似重复图片。文件哈希擅长发现字节级相同的内容，感知哈希则根据图像视觉特征判断“不同 URL 是否其实是同一张或高度相似的照片”。

不同 URL 也可能来自同一原图、同一 CDN 或不同尺寸的副本，因此不能只按 URL 判断唯一性。去重后若数量不足，可以扩展候选池，但不能为了凑数重复展示相同图片；去重解决的是重复，不负责证明图片与景区匹配。

## 语义匹配

视觉模型会结合景区名称、城市和图片内容输出匹配分，用于发现同名景点、附近 POI、城市通用宣传图或公共图片元数据错误。低于阈值或语义明显不一致的图片应被排除。

图片的文本元数据只能作为辅助证据。文件名包含景区名不代表图片一定正确，因为上传者可能命名错误、复用模板或把城市图片标成具体景点。最终应结合图片来源、页面上下文、视觉内容和实体信息共同判断。

## 来源展示

每张入选图片应尽量保留来源类型和来源页面。来源可以包括高德、官方文旅页面、景区官网、Wikimedia Commons 或本地回退占位。

来源展示让用户可以判断图片的可信度和使用边界。没有来源或来源不可核验的图片不应被描述为官方图片，也不应仅因为出现在景区页面就默认为官方发布。来源缺失时应明确写“来源待核验”，不要补造版权、作者或官网链接。

## 图片问题如何解释

回答图片相关问题时，先用一句话区分问题类型，再给原因：

1. 图片少：可能是高质量候选不足、语义匹配严格或去重后数量下降。
2. 图片模糊：从原图分辨率、压缩与缩放、页面展示尺寸三个环节解释。
3. 图片重复：哈希用于发现相同或近似内容，不同 URL 仍可能是同一张图。
4. 图片不匹配：说明视觉语义和来源校验，并承认自动筛选不能保证百分之百正确。

不要把“已缓存”描述成“已核验”，也不要把“来自官方页面”扩展成“当前信息永久有效”。
